# Project instructions

Read `ARCHITECTURE.md` before any structural change: creating, moving, renaming or deleting files, adding a tool, changing a runner stage, changing a classification rule, or changing an item type, state, field or relationship. Run its section 5 compliance check and report the result before implementing. A conflict with a principle or decision is a STOP until the user explicitly overrides it; record approved overrides under its Deviations section.

Run `tools/check-all.sh` before committing. It must be all ok.

Australian English. No em dashes in any document. Bump the version line of any document you change.

Append a line to `LOG.md` for every commit worth knowing about later, and record deferred work in `ENHANCEMENTS.md` rather than leaving it in conversation.
